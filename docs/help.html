UICTL(1)

uictl — find, inspect, and drive running Windows GUI applications

Synopsis

uictl subcommand [options]
uictl [-h | -H | --help | --HELP | -?]

Description

uictl locates running processes, lists and activates their windows, enumerates connected monitors, screenshots windows or displays (optionally with a numbered UI Automation element overlay), walks their UI Automation tree, clicks, types, sends key combinations, waits for elements to appear, runs OCR, samples pixel colors, and reads/writes the clipboard. It can also pin itself to one window so a human's own mouse/keyboard use doesn't steal focus mid-automation (focus hold).

A small background daemon (auto-started on first use, listening on a named pipe at \\.\pipe\uictl) holds the UI Automation engine and the element-id cache across invocations. It can also show two small on-screen windows of its own: a brief toast per command, and a live activity-log window (log show) with the option to export that log as JSON and a "Commands enabled" kill switch.

Every subcommand prints exactly one JSON object to standard output and exits 0 on success, non-zero on failure. This output is intended to be consumed by scripts or AI agents as readily as by a human. uictl can also run as an MCP server over stdio; see the mcp subcommand below.

Subcommands

daemon [start|stop|status] [--foreground]
Manage the background daemon. start is invoked automatically by any other command if the daemon isn't already running. --foreground runs it attached to the current console instead of spawning a detached process (used internally to bootstrap the daemon; also useful for watching daemon.log live).
permissions [--app <selector>] [--request]
Check this process's own elevation status, and optionally a target app's. --request is a no-op on Windows (kept for CLI parity with macOS, which uses it to trigger TCC consent prompts) - there is no equivalent OS consent dialog here, only "run uictl elevated too, or don't automate elevated apps."
apps [--all]
List running processes.
displays
List connected monitors: index (matches what screenshot --screen expects), the monitor handle as displayId, global-coordinate bounds, primary-monitor flag, and DPI-derived scale (physical pixels per unit at that monitor's current setting).
windows [--app <selector>]
List on-screen windows, optionally filtered to one app (name substring, package family name, or pid). Each window includes a displayId matching one from displays, or null if its center falls outside every monitor's bounds.
activate --app <selector> [--window <id>]
Bring an application, and optionally a specific window, to the front.
focus hold [--app <selector>] [--window <id>]
Pin uictl to one window - click/move/scroll/type/key will each re-activate it first if a human's own input steals foreground status mid-automation. Only the first hold in a hold/[hold...]/release sequence snapshots what was frontmost beforehand, for release to restore.
focus release
Stop pinning focus and restore whatever was frontmost right before the first hold in the sequence.
focus status
Show what's currently held, if anything, whether it's frontmost right now, and what release will restore focus to.
screenshot (--window <id> | --app <selector> | --screen <n>) [--out <path>] [--annotate] [--role <ControlType>]
Capture a window or display to a PNG file. With --annotate, overlays a numbered box on every UI Automation element and returns a JSON legend mapping numbers to element ids, roles, titles, and frames.
elements (--window <id> | --app <selector>) [--role <r>] [--title <substr>] [--maxDepth <n>] [--maxElements <n>]
Walk a window's UI Automation tree; returns each matching element's id, role (ControlType), title, value, and on-screen frame.
click (--at <x,y> | --element <id>) [--button left|right|center] [--double] [--count <n>]
Click at a screen point or on the center of a specific element, via SendInput - not UI Automation's InvokePattern, since many custom-drawn controls don't implement it. If a focus hold is active, re-activates the held window first; the response's focusHold field reports alreadyFrontmost/reactivated/failed.
move --at <x,y>
Move the mouse cursor without clicking (e.g. to trigger hover states).
scroll --at <x,y> [--dx <n>] [--dy <n>]
Scroll at a screen point.
type <text> [--element <id>]
Type text into the focused control, or into a specific element by id - tries UI Automation's ValuePattern.SetValue first, falls back to focusing the element and sending synthesized keystrokes.
key <combo>
Send a keyboard shortcut, e.g. ctrl+shift+esc. Modifiers: ctrl, shift, alt, win.
wait-for (--window <id> | --app <selector>) [--role <r>] [--title <substr>] [--timeout <seconds>]
Block until a matching element appears, or the timeout elapses (default 10s).
ocr (--image <path> | --window <id> | --app <selector>) [--region <x,y,w,h>]
Recognize text in an image file or a captured window (via Windows.Media.Ocr), optionally restricted to a region. Unlike macOS, no per-block confidence score is available - it's always reported as null.
pixel --at <x,y>
Sample the color of a single screen pixel.
clipboard (get | set <text>)
Read or write the system clipboard.
log show
Open the on-screen activity log window: a live table of every CLI/MCP call this daemon has handled, with an "Export JSON…" button and a "Commands enabled" checkbox. If it gets buried under other windows, run this again to bring it back to front.
log export [--out <path>]
Export the activity log as JSON (defaults under %LOCALAPPDATA%\uictl\exports\). Params/response values are the same summarized/truncated/redacted form shown in log show's table, not necessarily the exact raw payload for calls whose output was longer than the truncation limit.
feedback create --category <issue|error|recommendation> --title <t> --body <b>
Draft a new local feedback entry about uictl itself. Stored locally (%LOCALAPPDATA%\uictl\feedback.json); nothing is sent anywhere until feedback submit.
feedback list
List all local feedback entries (drafts and previously submitted).
feedback get <id>
Show one local feedback entry in full.
feedback update <id> [--category <c>] [--title <t>] [--body <b>]
Edit a local feedback entry.
feedback delete <id>
Delete a local feedback entry.
feedback check-duplicates <id> [--repo <owner/repo>] [--token <t>]
Check this entry's title against existing GitHub issues (open and closed) without submitting anything. Needs a token if the repo is private - pass --token, set $GITHUB_TOKEN, or have gh already authenticated; otherwise reports that it couldn't check rather than blocking. feedback submit runs this same check automatically.
feedback submit <id> [--repo <owner/repo>] [--token <t>]
First runs check-duplicates; if a likely duplicate is found, the local entry is deleted and nothing is opened. Otherwise opens GitHub's new-issue page with this entry's title/body pre-filled (defaults to uictl's own repo) in your default browser - it does not create the issue; a human still has to review and click "Create" there. Running this command from a terminal is treated as your confirmation. The uictl_feedback_submit MCP tool instead uses MCP elicitation to ask you to review (and optionally edit) the entry first, since an agent may call it without you having typed anything yourself.
mcp
Run as an MCP server over stdio, exposing every capability above as an MCP tool (add via claude mcp add uictl -- uictl.exe mcp).

Options

-h, -H, --help, --HELP, -?Show help. All five spellings are accepted at the top level and are normalized onto System.CommandLine's native --help.

Examples

List an application's windows, then screenshot it with element numbers:

uictl activate --app notepad
uictl screenshot --app notepad --annotate --out C:\temp\notepad.png

Click the element numbered 7 in that legend's id field, then confirm:

uictl click --element 12345-7
uictl elements --app notepad --title "Expected Label"

Hold focus on a window before a sequence of actions, so a human clicking back into the terminal running uictl doesn't derail it:

uictl focus hold --app notepad
uictl type --element 12345-3 "some text"
uictl focus release

Files

\\.\pipe\uictl
Daemon IPC named pipe.
%LOCALAPPDATA%\uictl\daemon.log
Daemon stdout/stderr.
%LOCALAPPDATA%\uictl\screenshots\
Default output location for screenshot when --out is omitted.
%LOCALAPPDATA%\uictl\exports\
Default output location for log export when --out is omitted.
%LOCALAPPDATA%\uictl\feedback.json
Local storage for feedback entries (drafts and previously submitted).

Security

ocr, elements, and screenshot read whatever is genuinely on screen, which can include passwords, tokens, or other sensitive text an automated app happens to display; that content is not redacted (unlike type/clipboard set/clipboard get text, which is). It can end up in the activity log (log show, log export) and in screenshot files on disk. Manage and dispose of the activity log window, its exports, and saved screenshots with the same care as any other capture of your screen's contents.

UI Automation and SendInput are subject to Windows' UIPI (User Interface Privilege Isolation): if uictl runs unelevated and the target app is elevated, calls into it will fail or silently no-op. Run uictl permissions to check; if the target is elevated, run uictl elevated too.

Exit status

0 on success (the JSON response's ok field is true); non-zero otherwise.
